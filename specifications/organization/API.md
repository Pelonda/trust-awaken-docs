# Organization API Specification

## Purpose

This document defines the REST API for the Organization module.

The API allows Platform Administrators and authorized users to create, manage, and retrieve Organizations.

---

# Base URL

```
/api/v1/platform
```

---

# Authentication

All endpoints require authentication.

Authentication methods:

- Microsoft Entra ID
- Local Authentication
- Future Identity Providers

---

# Content Type

```
application/json
```

---

# Resource Identifier

Organizations are referenced by their **UUID**.

Example:

```
/organizations/9c0b5df4-1d4e-4b77-a97b-8d2d8b7b0d12
```

Database IDs are never exposed.

---

# Endpoints

## List Organizations

GET

```
/organizations
```

Returns a paginated list of Organizations.

---

## Get Organization

GET

```
/organizations/{uuid}
```

Returns a single Organization.

---

## Create Organization

POST

```
/organizations
```

### Request Body

```json
{
  "display_name": "Global CyberSafe",
  "legal_name": "Global CyberSafe Inc.",
  "organization_type": "nonprofit"
}
```

### Success Response

HTTP

```
201 Created
```

---

## Update Organization

PUT

```
/organizations/{uuid}
```

Updates editable Organization information.

---

## Archive Organization

DELETE

```
/organizations/{uuid}
```

Performs a Soft Delete.

Organizations are never permanently deleted through the API.

---

# Standard Response Codes

| Code | Meaning |
|------|---------|
| 200 | Success |
| 201 | Resource Created |
| 204 | No Content |
| 400 | Invalid Request |
| 401 | Unauthorized |
| 403 | Forbidden |
| 404 | Organization Not Found |
| 409 | Conflict |
| 422 | Validation Failed |
| 500 | Internal Server Error |

---

# Validation Rules

Required fields:

- display_name
- legal_name
- organization_type

The following values are generated by the server:

- uuid
- slug
- status
- owner_user_id

Clients must never submit these values.
